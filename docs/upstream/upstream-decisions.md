# 上游追踪决策

> 本文只记录上游追踪、取舍和移植过程中的决策，不记录 Pi 项目自身的架构或行为决策。
> 项目上下文决策见 `docs/context/design-decisions.md`。
> 更新日期：2026-09-15

## 当前有效决策

### 选择性追踪，不做未经分析的全量吞并

面对上千个上游提交，先固定 custom 起点和上游分析终点，比较整个窗口的净变化，再按语义依赖和功能闭包拆成波次。分析终点是边界，不是一次性 merge 目标。

### minor/tag 是分析锚点，不是自动合并批次

稳定 release、minor 版本和架构断点用于建立宏观时间线。一个 minor 周期如果包含多个相互独立的功能或大型重构，必须继续拆波次；一个功能闭包跨越多个 tag 时，也可以作为一个完整波次处理。

### 先看终点净变化，再定向回看历史

普通低风险变化优先依据起点到终点的最终 diff 判断。核心架构、行为契约、依赖升级和冲突文件再回看相关历史，以理解因果和前置关系。不为逐个读完所有上游提交而扩大范围。

### 每个波次必须可解释、可验证

波次至少应说明功能闭包、上游范围、custom 接入点、采纳/适配/冻结/排除决定、停止条件和验证门。无法单独解释或验证的混合批次继续拆分。

### 依赖升级与功能采纳分离

Cargo.toml、Cargo.lock、build.rs 和主依赖 API 变化不能因为文本上自动合并就默认接受。依赖升级需要和适配代码组成独立迁移波次，单独验证；普通功能波次默认保留 custom 依赖基线。

### 结构重构单独立项

extensions、VFS、核心 runtime、工具目录边界或其他已被 custom 重构的区域，不随普通功能波次顺手迁移。需要迁移时先形成独立设计、边界和停止条件。

### 完成闭包不重复迁移

Hub 最小闭包已在 custom 中完成；完成记录见 `plan-hub-minimal.md`。后续只比较上游相对当前实现的新增差异，不重复搬运已完成闭包。

## 历史追踪决策

### D46：依赖升级冻结

2026-08-16 的合并工作中，决定将 digest 0.11、SWC 26、asupersync 0.4、rquickjs 0.12、base64 0.23 等依赖升级整体回退到 custom 基线；build.rs 和引用新 API 的自动合入文件同样回退。原因是上游依赖升级伴随大量适配代码，直接升级曾产生 423 个编译错误。该升级不应与普通功能采纳混在一起，需作为独立迁移项目重新规划。

### D47：固定分析窗口，按语义闭包选择性处理

2026-08-16 制定、2026-09-15 重写的原则是：不按提交数量机械追上游，也不把移动的 `upstream/main` 全量合入 custom。先固定可复核的起点和终点，分析最终净变化，再按语义依赖和功能闭包分别决定采纳、适配、冻结或排除。文件结构已经分叉的区域优先独立移植或按 custom 语义适配；只有能够保持意图和归因的范围才使用选择性 merge。

### D55：Hub 全闭包采用独立移植

2026-08-29 的 Hub 处理采用单文件闭包移植，而不是全量 merge `upstream/main`。实际落地了 Hub、Jobs、Agent Hub、Subagents、Secrets、Worktree isolation 及必要的依赖和工具调度适配。全量探针显示，121 个冲突可以清零，但 297 个编译缺口和依赖漂移才是主要成本；Hub 闭包移植则在隔离范围内恢复到可验证状态。后续只处理该闭包相对 custom 当前实现的新增差异。

## 仍然有效的操作约束

- `main` 是上游镜像基线，`custom` 是二开主线；业务改动不直接提交到 `main`。
- 主仓库之外的合并试验使用隔离 worktree。
- 合并前先验证 custom 基线，避免把原有失败误归因于上游变化。
- 先记录待处理范围，再执行选择性 merge 或闭包移植。
- 发现依赖/API 漂移、结构边界不明或测试失败无法归因时停止扩大，并记录阻塞原因。
- 生成物、快照、checksum 和文档索引按其来源重新生成或更新，不把冲突标记数量当作语义价值。
- `.github/dependabot.yml` 中的 Dependabot 更新项保持禁用；未经明确授权，不把上游 bot 自动化带入 `main`。

## 历史证据入口

- `plan-hub-minimal.md`：Hub 最小闭包的完成记录与验证结果。
- `probe-report-2026-08-29.md`：全量 merge 探针及其依赖/API 漂移失败分析。
- `known-test-failures.md`：带日期和运行信息的测试基线；除非重新验证，不称为当前基线。

## 重新评估条件

以下情况出现时，需要重新审视当前追踪策略，而不是自动恢复全量 merge：

- custom 完成与上游结构重构对应的独立迁移；
- 主依赖升级已有完整适配和验证方案；
- 上游发布或行为契约变化要求同步持久化/协议边界；
- 当前终点已不再能代表想要支持的上游能力范围；
- 新证据表明某个冻结域其实可以形成独立、低风险的功能闭包。
