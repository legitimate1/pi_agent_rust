# 上游语义波次计划

> 当前状态：框架待填充。本文不按提交数量预先切成固定阶段；每个波次必须对应一个可解释、可验证的语义闭包。
> 更新日期：2026-09-15

## 核心模型

```text
分析窗口：custom 上游起点 S ───────────────► upstream 终点 T
                                      （只定义研究边界）

实际处理：                         语义波次
                                      ├─ 采纳
                                      ├─ 适配
                                      ├─ 冻结
                                      └─ 排除
```

minor/tag/release 只提供宏观时间刻度。真正的波次边界由以下因素决定：

- 功能是否形成闭包（类型、实现、调用方、测试和必要文档）；
- 是否存在依赖或 API 前置条件；
- 是否跨越 custom 已经重构过的文件边界；
- 是否触发核心契约、持久化格式或运行时变化；
- 完成后能否单独验证和解释。

## 波次状态

- `候选`：已从分析窗口识别，但尚未完成语义判断。
- `准备`：范围、前置依赖和验收门已明确，可以开始处理。
- `处理中`：正在进行选择性 merge 或独立闭包移植。
- `已完成`：决策、实现和验证证据齐全。
- `冻结`：本窗口明确不处理，保留原因和重新评估条件。
- `排除`：确认不属于 custom 的目标，不纳入后续追踪。
- `需复审`：新证据推翻了原来的边界或前置假设。

## 当前已知的历史结论

以下不是本窗口的自动波次，只是重建时必须尊重的已有事实：

### 已完成：Hub 最小闭包

Hub/Jobs/Agent Hub/Subagents/Secrets/Worktree isolation 的最小闭包已经在 `custom` 中落地。完成证据见 `plan-hub-minimal.md`，长期决策见 `docs/context/design-decisions.md` 的 D55。

本波次不得重复迁移；若未来需要 Roster、Jobs UI 注入点或其他上游后续增量，应另建小波次并先确认与当前实现的差分。

### 默认冻结：主依赖代际升级

`asupersync`、`rquickjs`、SWC、digest、wasmtime、Rust toolchain 等主依赖升级不能因为 merge 没有文本冲突就自动采纳。必须把依赖升级和对应 API 适配作为独立波次，单独估算、实现和验证。

### 默认冻结：结构性扩张

extensions 多文件化、VFS 语义、发布管道、上游内部 Beads/swarm 数据和其他与当前 custom 结构强耦合的变化，默认不随普通功能波次带入。若要处理，必须先建立独立设计和迁移边界。

## 推荐的规划顺序

1. 从 `analysis-window.md` 固定 S、T 和 minor/tag 锚点。
2. 先识别低风险、独立且有实际价值的基础修复。
3. 单独标出依赖/API 代际和核心契约变化。
4. 按功能闭包整理 tools、providers、session、TUI、extensions 等主题。
5. 对每个主题决定采纳、适配、冻结或排除，不把标签直接当结论。
6. 只有准备处理的波次才深入查看相关提交历史。
7. 每完成一个波次就验证并记录证据；不要跨波次累积无法归因的修改。
