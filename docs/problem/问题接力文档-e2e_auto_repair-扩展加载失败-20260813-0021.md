# 问题接力文档 - e2e_auto_repair 全量测试 1 红（3 个扩展加载失败）

## 问题
- 最终目标：`cargo test --test e2e_auto_repair` 转绿（或明确判定哪些失败可豁免），使收尾门禁（全量 `cargo test`）不再被该测试绊住。
- 现象：`full_corpus_with_auto_repair` 断言失败（`tests/e2e_auto_repair.rs:475`）：`Extensions failed to load even with auto-repair`。汇总 `Total: 224 | Clean: 219 | Repaired: 0 | Failed: 4 | Skipped: 1`；报告见 `tests/ext_conformance/reports/auto_repair_summary.json` / `auto_repair_report.md`。
- 复现步骤：
  1. `cargo test --test e2e_auto_repair`（Windows，仓库根目录）
  2. 观察 `=== Auto-Repair E2E Summary ===` 与断言 panic
  3. `is_nonblocking_auto_repair_failure()`（tests/e2e_auto_repair.rs:307）判定豁免后，剩 3 个 real_failures 触发 panic
- 环境：Windows（Win10/11）+ Rust nightly；`tests/ext_conformance/artifacts/` 下的扩展语料（npm-registry / third-party-github / official-pi-mono 等 tier）；node:fs shim 在 `src/extensions_js.rs`。

## 当前推测
- 最可能根因（3 个 real_failures 各自独立）：
  1. `npm/agentsbox` — 扩展不支持 Windows（自身 `Unsupported OS: win` 检查），非本项目 bug；正确动作是**加入豁免清单**（`is_nonblocking_auto_repair_failure` 增加 "Unsupported OS" 分支，限定 id=npm/agentsbox + tier=npm-registry，保持精确）或标记 skipped。
  2. `third-party/w-winter-dot314` — `fs.watch(RESULTS_ROOT)` 时 `.pi-subagent-tmp/pi-async-subagent-results` 目录不存在 → ENOENT；扩展应在 watch 前 `mkdirSync(recursive)`。可选项：A) 修扩展源码（fork 语料，加 mkdir）；B) 加豁免（需要慎重，避免掩盖真实回归）；C) 报告给扩展作者。
  3. `third-party/jyaunches-pi-canvas` — 错误堆栈同样指向 `w-winter-dot314/subagent/index.ts:97:30`（**同一 watch 调用点**），与 #2 同根因，一并处理。
- 已否决的根因：
  - 「node:fs shim 的 watch 行为有 bug」— 否。真实 Node.js 对不存在路径的 fs.watch 同样抛 ENOENT（可本机 `node -e "require('fs').watch('no-such-dir')"` 验证），shim 行为对齐 Node。
  - 「本次 drop-in 降级 / JobObject 改动引入」— 否。git stash 对比确认原始 HEAD 同样失败。
  - 「缺 artifact 文件（claude-rules）」— 已豁免，不是断言失败原因（但作为已知问题可另处理：`tests/ext_conformance/artifacts/claude-rules/claude-rules.ts` 缺失）。
